# Exercise technique tutorials

Use **Watch technique** beside an exercise in **Programs → Exercise library**, or the play control beside the current exercise during a workout. Tutorials load only when opened. The dialog shows the source, instructor, duration and any variation notes.

## Selection review — 16 October 2026

All 57 exercises were reviewed. 49 links were replaced and eight substantive existing tutorials retained. The catalog has 55 distinct videos; the three incline dumbbell press angles share one tutorial with explicit angle notes.

Selection prioritizes the actual movement and equipment, clear setup/execution/error correction, and a focused explanation from an established instructor. Most videos run at least three minutes. One deliberate exception is Nick Tumminello’s complete 2:25 landscape lesson for the single-arm cable press. It teaches the exact movement and successfully plays inside the app; it is not a YouTube Short. Broader videos identify the exercise variation and link to the relevant chapter where supported.

The final selections were all observed playing inside the app using YouTube’s official IFrame API: state PLAYING, matching source ID, no player error, and actual landscape video dimensions. This is stronger evidence than an oEmbed response or a watch-page thumbnail. The live review rejected an embedding-disabled decline tutorial (error 150), a portrait shoulder-press tutorial, and a portrait seated-curl clip before choosing the final replacements. Current video availability can still change with the publisher or region.

The actual player now meets YouTube’s [minimum 200×200 viewport](https://developers.google.com/youtube/player_parameters), including on phones, sends an identifying origin/referrer, and permits fullscreen and playback. Chaptered lessons set both start and end times so unrelated exercises do not continue in the app. These settings follow the [official player parameters](https://developers.google.com/youtube/player_parameters) and [embedding guidance](https://support.google.com/youtube/answer/171780?hl=en). The embedded player does not autoplay in ordinary use.

## Verification and maintenance

- Catalog: `src/data/exerciseVideos.ts`. Updates are independent of saved exercise definitions, workout history and cloud data; no migration is needed.
- Playback evidence: `output/exercise-video-playback-verified.json` records each final source’s actual player state, duration, ID, dimensions and check time.
- Deterministic checks: `pnpm test:run tests/features/exercise-technique.test.tsx tests/features/dialog-surface.test.tsx` and `pnpm test:e2e tests/e2e/exercise-technique.spec.ts tests/e2e/workout-design.spec.ts`. Normal browser tests stub remote frames.
- Live acceptance check: in PowerShell, set `$env:VERIFY_YOUTUBE_PLAYBACK = '1'`, then run `pnpm test:e2e tests/e2e/exercise-technique-live.spec.ts`. This briefly plays each distinct source muted inside the app and checks landscape dimensions, runtime and chapter start. The test is skipped during ordinary offline CI.
- Optional preliminary metadata check: `node scripts/verify-exercise-videos.mjs`. This is rate limited and cached, and intentionally stops further network requests if YouTube responds with 429. Metadata alone cannot establish actual video orientation or successful embedded playback.

Offline users see a connection message and can retry when connectivity returns. **Open on YouTube** remains available for a later publisher restriction or other player problem. Custom or unknown exercises offer an exercise-specific YouTube search.

The development server retires a stale production service worker at `/sw.js`, deleting only `forge-shell-*` caches and preserving saved records. The recovery regression is `tests/e2e/dev-preview-cache.spec.ts`.

Final verification: production build and lint passed; 12 focused component/dialog tests passed; 16 browser tests passed, including actual muted in-app playback for all 55 distinct final videos, chapter starts, minimum mobile player size, library containment, saved workout entries and short-phone layouts.
